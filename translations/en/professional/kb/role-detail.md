# Role Details

Configure detailed permissions and system access for a specific organizational role.

## What you can do here

- Review and modify the complete permission set for a role
- Control which modules and features the role can access (clients, engagements, billing, reports, admin settings)
- Set data access restrictions (can view all clients or only assigned clients, etc.)
- Configure approval authority and workflow permissions for the role
- Define billing and financial permissions (view rates, edit invoices, approve payments, etc.)
- Establish reporting and analytics access levels for the role

## Common workflows

**To add a permission to a role:** Open the role and navigate to the Permissions section. Click "Add Permission" and select the desired capability (e.g., "Edit Client Billing", "Approve Matters Over $10K"). Save the change.

**To restrict a role's data access:** In the Data Access section, toggle between "All Records" and "Assigned Records Only" depending on the role's responsibilities. Assign specific clients if using restricted access.

**To set up approval authority:** Configure which actions this role can approve (new matters, budget changes, invoice adjustments, rate overrides) in the Approvals section.

**To grant financial permissions:** Navigate to Financial Settings and enable or disable permissions such as "View Billing Rates", "Edit Client Invoices", "Approve Payments", and "Access Profitability Reports".

**To configure audit and compliance permissions:** Set which reports the role can access, whether they can export data, and if they can view team member utilization or billing information.

## Tips

- Start with restrictive permissions and add access as needed rather than removing permissions later
- Document the intended purpose of each custom role and its permission set for future reference
- Test custom roles with a single team member before rolling out to multiple staff
- Use role-based data restrictions (assigned records only) for junior staff to limit sensitive client information exposure
- Review role permissions quarterly as your practice structure evolves and new modules are added to the system
